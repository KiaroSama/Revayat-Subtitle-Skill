## 3. Confirmed defects and implemented solutions

The numbered entries below are defect groups. Multiple failing examples or subtests are evidence for a group, not additional independent bugs.

### F01 — ASS dialogue was interpreted as SRT markup a second time

**Impact: high; subtitle content and rendering change.** Native ASS text such as `Type <i> here.`, a literal `<br>`, or an explanatory `<font color=...>` was passed through `process_cue_text(..., kind="ass")`, whose historical API performs SRT-to-ASS conversion. Literal text became style controls or line breaks. Width and direction calculations also treated HTML-looking ASS prose as hidden markup.

**Implemented repair:** `text_pipeline.process_ass_text` handles already-decoded ASS; `subtitle_formats.py` and `workflow.py` call it after the explicit input-format boundary. The existing generic API remains compatible. Python tokenization uses the actual format grammar, and `rust/subcore-rs/src/port/tokens.rs` supplies matching native spans, including escaped braces and drawing mode. SRT markup is still converted once.

**Closure evidence:** `tests/test_audit_pipeline_20261124.py` covers literal tags, CLI conversion, visible width, direction, and real FFmpeg/libass raster equivalence. The raster comparison failed before the fix and matches afterward with the same styles. Review both native ASS and genuine SRT conversion; fixing one by disabling conversion globally is unacceptable.

### F02 — A link or credit marker could delete spoken dialogue

**Impact: high; entire cues disappear.** The watermark classifier searched for substrings anywhere in an event. `Open https://example.test to read the manual.`, dialogue mentioning OpenSubtitles, and Persian dialogue mentioning a channel could all be discarded. Dialogue on one display line plus a URL on another was also removed as a single event. Credit-prefix clauses require the same conservative treatment: `Downloaded from the device, the files contain evidence.` is spoken prose, not a download advertisement.

**Implemented repair:** Python and Rust classify complete display lines and remove a cue only when every nonempty line fits a supported standalone credit/advertising form. Clear standalone URLs, handles, sites, and attribution forms remain recognized; mixed dialogue is retained. Prefix attribution accepts an explicit URL, a handle, or one identifier/name token. Free-form multiword tails are retained for editorial review, including both short clauses and multiword names. This conservative lexical contract replaces the initial word-count heuristic that still deleted `Subtitles by amateurs are unreliable.`; lowering that threshold or adding a verb blacklist is not an acceptable fix. Documented `--keep-watermarks` remains available when semantic ambiguity requires editorial control.

Classification now also receives the actual input format at every production call site. ASS HTML-looking text remains literal; SRT removes only supported formatting and complete comments from the classification projection. Decoder-recognized but unsupported SRT tags, and unsupported ASS control syntax, remain available to the existing conversion validator, which refuses them explicitly before creating output. This closes the additional reproduced cases `<notice>https://example.test</notice>` in SRT and `<i>https://example.test</i>` in ASS. URL, site-path, and Telegram-path patterns all exclude raw markup/control delimiters, including trailing literal tags. Python and PyO3 preserve one-argument SRT API compatibility and accept an explicit format. The compiled contract revision described in F07 prevents new Python from delegating to incompatible older binaries across the whole accelerator; genuine internal native errors are not hidden.

**Closure evidence:** the pipeline audit corpus contains retained-dialogue examples, mixed multiline cases, a build that previously lost its only cue, and positive controls for actual credits. A public CLI conversion covers 15 cues: 12 retained dialogue/ambiguous attribution cues and 3 genuine credits removed, with the source unchanged. Cases include short clauses, uppercase, punctuation, line breaks, Persian text, multiword names, single names, URLs, and handles. Native differential tests must agree with the Python result. Do not replace these tests with an assertion that every string containing a URL is advertising. No deterministic string classifier can certify dialogue meaning; review remains necessary.

Format regressions additionally exercise direct classification, actual ASS/SRT CLI conversion, SRT workspace upgrade, Translator Mode donors, supported/unsupported formatting, URL-first trailing markup, comments, escaped braces, invalid format values, and stale native bindings. Unsupported decoder markup produces a clear refusal with no output; a tag exceeding the decoder's recognition limit stays literal and is preserved. Neither case may silently shorten a subtitle. Both native APIs and the public Python path must obey the same format contract.

### F03 — Review links could become invalid during the final build

**Impact: high; approved source coverage is lost.** `assemble` validated links against pre-normalization retained cues. Watermark removal could then eliminate the linked target after the donor had been marked `alternate`, leaving neither in the generated edition. Self-links were also accepted by build despite being rejected by handoff validation.

**Implemented repair:** `workflow.assemble` rejects self-links and checks all decision links against the actual emitted provenance keys after normalization and before publication. A worksheet with a removed linked target fails clearly. Correcting the worksheet permits a successful retry.

**Closure evidence:** pipeline regressions assert failed publication for self-links and removed targets, followed by successful corrected retry. Preserve source/decision identity and existing same-episode retained-cue constraints; do not merely suppress the error or automatically relabel an alternate.

### F04 — Translator Mode changed overlapping ASS presentation order

**Impact: high for layered signs/effects.** Translator Mode globally sorted primary events and set `chronological=True`, overriding the serializer's overlap-preservation contract. Same-layer compositing and collision placement could change without a text or timing edit.

**Implemented repair:** sorted primary cues are used only for timing lookup. Final output uses `presentation_order` to preserve original read order within connected overlap components while ordering independent components and new slots. Source comment associations remain tied to cue IDs.

**Closure evidence:** an authored nonchronological overlapping ASS case, a deliberately reversed negative control, and actual FFmpeg raster comparisons. The reversed control produces different pixels; the repaired result matches the source. Existing non-overlapping chronological behavior continues to pass. Merely asserting increasing timestamps would reintroduce this defect.

### F05 — Repeated unmatched comment openers caused quadratic processing

**Impact: medium; modest malformed input stalls conversion/normalization.** A shared lazy comment regex repeatedly searched for a missing terminator. An 80 KB authored string exceeded a 2-second owned-process deadline; a 200 KB regression also failed its original 8-second bound.

**Implemented repair:** the common scanner recognizes `<!--`, locates the terminator once, and remembers when none exists in the remaining suffix. Complete comments stay protected; unmatched openers remain literal. Python and Rust preserve precedence with ASS overrides and HTML attributes, including comment-looking text inside tags.

The complete release-native run exposed a second part of this defect: even after comment scanning was linear, unanchored `fancy_regex` verb/compound searches exhausted their generic backtracking budget while walking the long unrelated prefix. The native repair finds candidate initial letters with a linear regex, then evaluates the full unchanged rule at that byte position with its surrounding context. It does not increase the regex limit, extend the timeout, or fall back to Python.

**Closure evidence:** the final regression uses 100,000 unmatched openers, 400 KB total, with a 10-second owned-process deadline to allow cold-start margin. It also places all four real Persian normalization forms after that prefix, checking preserved prefix bytes and corrected tail text. A native unit covers the same case. Additional tests cover real comments and surrounding tags. This is a bounded complexity regression, not a claimed throughput benchmark. Do not solve it by truncating subtitle text or raising the timeout indefinitely.

### F06 — Persian code protection swallowed prose and corrupted literal NULs

**Impact: medium; missed typography corrections and lost/reordered protected text.** In the bundled Persian linter, a DOTALL regex intended for fenced code also applied `.*$` to indented lines. One indented code line protected all following paragraphs. Separately, literal NUL characters collided with mask placeholders; `before\x00` followed by two inline code spans could consume the wrong spans and drop the last code fragment. Both defects existed in the Rust port too.

**Implemented repair:** limit the indented-code alternative to its own line while preserving multiline fenced blocks; protect existing NULs as their own spans so restoration retains order and bytes. Mirror the changes in `rust/persian-lint-rs/src/port.rs`. The touched standalone CLI now provides timestamped INFO/WARNING/ERROR/DEBUG diagnostics on stderr, validates its log level, and avoids logging source content.

**Closure evidence:** `tests/test_audit_install_native_20261124.py`, native parity, and Rust units cover spaces/tabs, LF/CRLF, following normalization and suggestions, fenced blocks, multiple NULs, protected internal NULs, idempotence, diagnostic redaction, and invalid log-level refusal. Existing voice-script tests also run.

### F07 — Native behavior diverged across Python versions and old binaries

**Impact: medium; optional acceleration changes output.** Compiled modules were not being compared against the Python reference across the supported interpreter range.

- HTML attribute decoding: on Python 3.12, native `srt_font_names('<font face="&amp=">')` returned `{'&amp='}` while the reference returned `{'&='}`. Maintained CPython versions have different HTMLParser attribute-decoding contracts.
- Bidi classification: hardcoded Rust Unicode 15.1 differs from Python 3.11's Unicode 14 and Python 3.14's Unicode 16. U+1171E, U+1D6C1, U+1C89, and U+10D40 exposed incorrect detection and internal `rtl()` behavior.
- Subcore anchoring and Persian word boundaries also differed for newly assigned characters, including U+1E4D0 adjacent to Persian verb/plural/enclitic/compound rules. Correcting only exported detection helpers leaves internal transformations inconsistent.
- Watermark attribution had the same boundary problem: `Subtitles by ` followed by U+1E4D0 or U+1C89 could be deleted by native code while Python 3.11 retained it. Both watermark decision APIs now apply runtime word classification after native preprocessing and case folding; the four failing decision subtests are covered.

**Implemented repair:** detect the running interpreter's attribute-decoding contract; use its Unicode properties at the PyO3 boundary for distinct relevant characters, passing classification into the actual Rust transformations. Keep normalization/tokenization/rewriting in Rust. Apply the contract inside the pipeline, not only in facade functions. Standalone Rust units retain a deterministic default Unicode contract.

**Upgrade boundary:** all three compiled modules and their current Python facades expose and verify `REVAYAT_NATIVE_CONTRACT = 1`. A current facade rejects an incompatible compiled module with an actionable `ImportError`. The existing Subcore dispatcher also checks the whole-module contract, so an entirely old installed facade safely uses the current Python implementation for every operation. Markup and Persian-linter libraries currently have no automatic production dispatcher; this repair does not invent one. The watermark-specific feature flag remains separate from the shared contract revision. Do not gate only watermarks or maintain a partial list of line helpers: an ABI-loadable old binary can also restore obsolete wrapping, anchoring, normalization, entity, Unicode, and protected-span behavior. Preserve the contract checks during generator refreshes and update the contract deliberately when native/reference semantics become incompatible.

Actual baseline binaries reproduced the stale behavior on Python 3.11, 3.12, and 3.14: missing ASS line breaks/RTL anchors and old Persian-linter span handling; old entity decoding also failed on 3.11/3.12 and a newer Unicode classification on 3.14. The regressions require rejection of old/missing/future contract revisions, preserve modern native delegation and explicit disable behavior, and verify that internal native exceptions still propagate. This is compatibility negotiation, not an authenticity or security boundary.

**Closure evidence:** `tests/test_native_parity.py` directly calls every exported API of all three real compiled extensions and compares values and expected exceptions against Python, with native dispatch disabled only on the reference side. It includes legacy/modern entity handling, version-sensitive Unicode, markup, drawings, bidi scopes, wrapping, Persian protected spans, and deterministic mixed-text cases. `REVAYAT_REQUIRE_NATIVE=1` must fail if modules are unavailable. Do not pass by silently falling back to Python or skipping the native lane.

### F08 — Install history could permanently poison recovery

**Impact: high for affected installations.** The registry reader allowed 1,000 entries but registration wrote a 1,001st. Completed bindings were never retired. After enough successful installations, install and rollback failed, and subsequent recovery rejected the registry. A process ending after a terminal journal write but before unregister also left a completed transaction occupying active capacity.

**Implemented repair:** `install/install_state.py` defines the capacity once, retires only oldest inactive bindings before registration, and refuses an all-active full registry before mutation. It admits the exact bounded legacy overflow of one extra schema-valid row so old interrupted state can be recovered. Authenticated `committed`/`restored` journals are reconciled when their unregister step was interrupted. Retirement preserves journal and backup files and never evicts active nonterminal recovery records.

**Closure evidence:** real isolated installs at capacity, active-entry preservation, unchanged registry bytes on all-active refusal, old 1,001-row state followed by explicit recovery twice and another install, and the terminal-write-before-unregister crash window. A fix that only prevents new overflow without recovering existing poisoned state is incomplete. Preserve registry authentication, ownership locks, safe paths, and foreign-state refusal.

### F09 — Sync mishandled CR-only and mixed line endings

**Impact: medium; valid subtitle input fails or cues are missed.** The Rust sync parser split only on LF. CR-only SRT failed timestamp parsing; mixed-ending ASS could be misdetected or partially parsed.

**Implemented repair:** `rust/subsync-rs/src/formats.rs` scans CRLF, LF, and CR explicitly, preserving original byte ranges. Format detection uses the same scanner. Serialization preserves the parsed cue payload and original line endings while replacing timestamps. The pre-existing removal of an initial BOM is unchanged.

**Closure evidence:** native round trips and real-engine Python tests assert cue count, text/tag preservation, and exact line-ending preservation for all styles and mixed ASS. A rewrite that normalizes every file to LF would violate the contract.

### F10 — Missing SRT separators produced misleading partial sync success

**Impact: high; only part of the document is retimed.** A later timing row without the separating blank line was swallowed as the previous cue's text. The engine successfully retimed the first parsed cue and left the later timing rows unchanged. Both numbered and unnumbered SRT variants were affected.

**Implemented repair:** recognize a syntactically valid timing row inside an existing cue body and refuse it with a line-specific `missing SRT cue separator` error. Do not guess whether an ambiguous embedded timing row is text or a new cue.

**Closure evidence:** native and real CLI tests cover numbered and unnumbered cases; neither subtitle nor report is published and source bytes remain unchanged. Add the missing separator, then retry. Do not accept a lower cue count as successful whole-document alignment.

### F11 — Constant audio activity caused a false FPS correction

**Impact: medium; successful-looking wrong timing.** A 10-second authored 400 Hz tone yielded only active VAD frames. Although before/after overlap was already `1.0`, sync selected FPS ratio `1.0427093760427095` and shifted starts by up to `192 ms` without any silent timing anchors.

**Implemented repair:** reject all-active timelines before mutating the document. Existing silence rejection remains. This narrowly addresses absent timing evidence; it does not pretend to identify every music/dialogue mixture or the correct speaker.

**Closure evidence:** constant-tone refusal, deterministic broadband noise, silence, no output on failure, valid offsets, FPS drift, and edits. A 12-minute authored VAD timeline with 192 cues and 12 independently shifted sections verifies every final timestamp and contiguous split coverage. Overlap scores remain mechanical indicators requiring listening review.

### F12 — Sync write/report failures left misleading final files

**Impact: high; partial output blocks safe retry.** Subtitle/WAV writers created final filenames before completing writes. A real Linux `RLIMIT_FSIZE=128` failure left a 128-byte truncated subtitle, which blocked the next attempt. A read-only report directory failed only after the subtitle had already been published.

**Implemented repair:** new `rust/subsync-rs/src/publication.rs` stages complete files in their destination directories, flushes and `sync_all`s them, and uses `NamedTempFile::persist_noclobber`. `Cargo.lock` pins tempfile 3.27.0. Fully stage both subtitle and optional JSON report before publishing either. The WAV helper shares the complete-file writer. Existing destinations and race winners are never overwritten.

**Boundary that must remain explicit:** two output names are not one portable atomic transaction. If another writer claims the report name after staging, the subtitle can already be complete. Return the specific diagnostic identifying that subtitle, preserve the winning report, and do not delete another writer's file to fake rollback. This is not a power-loss durability guarantee.

**Closure evidence:** actual kernel write failure plus successful same-path retry; report staging failure plus retry after permissions are restored; injected native write failure on every OS; both publication-race orders; source/output/report identity, hardlink and symlink cases. On ordinary staging failure, neither final file exists. On the late second-file race, exactly the complete subtitle and preserved independent report remain.

### F13 — Package CLI followed a dangling destination symlink

**Impact: medium; publication occurs under an unrequested name.** The package CLI called `args.out.resolve()` before the no-clobber publisher. An occupied dangling `Sub.zip` symlink was resolved to another filename; packaging returned success and created that target instead of refusing the occupied requested leaf.

**Implemented repair:** `revayat-subtitle.py` passes `args.out.absolute()` to the existing exclusive publisher, preserving the leaf for its collision check. Build-path resolution is unchanged.

**Closure evidence:** `tests/test_cli_publication.py` creates a genuinely reviewed authored build and invokes the actual CLI. Baseline exit was 0; corrected exit is 2, the symlink remains, and its target is not created. Existing delivery/publication tests remain required. Do not replace exclusive publication with an overwrite or delete the user's link.

### F14 — Main CI did not run automatically and native tests could hide gaps

**Impact: high for regression prevention.** The main workflow was dispatch-only. The baseline did have a successful manually dispatched run, but a subsequent commit or PR was not guaranteed to show the core checks. The previous accelerator lanes built/imported modules without full Python-versus-native differential execution; native Rust units also needed portable linking configuration.

**Implemented repair:** `.github/workflows/ci.yml` runs on main pushes, PRs, merge-group checks, dispatch, and reusable calls, without path filters. `CI required` depends on every validation group and fails if any group is failed, cancelled, or skipped. The native matrix builds all three actual extensions on Linux/Python 3.11 and 3.14, Windows/3.14, and macOS/3.14; stages the interpreter-specific ABI suffix; and runs the full Python suite with mandatory native parity. The sync matrix uses all three OSes and requires FFmpeg. Releases call this same workflow before artifact building.

**Portable native units:** each accelerator exposes a default `extension-module` feature; normal extension builds retain it. Test binaries use `cargo test --locked --no-default-features --lib`, with the macOS dynamic-lookup linker flag conditional on extension mode. Formatting, Clippy, locked builds and units all run. The pinned `rust-toolchain.toml` supplies the toolchain rather than an implicit latest release.

Independent workflow review also caught and corrected a concurrency interaction before publication: different release tags dispatched from the same branch must not cancel each other's reusable validation. The caller supplies its run ID as `validation_id`; ordinary standalone CI still cancels obsolete runs for the same ref. This conclusion follows GitHub's documented caller-context/concurrency semantics and a source-policy regression; no live signed release was dispatched to reproduce it.

**Closure evidence:** automatic-trigger/no-path-filter policy tests, real staged extensions, actionlint, zizmor, and the actual latest-revision GitHub run. Branch protection/ruleset configuration must designate the required check where the owner’s Rules require it; a YAML job alone does not configure repository settings. Keep the check visible on every final PR/default-branch revision.
