## 2. R01 — A later end extension legitimizes an impossible earlier snap

**Impact and reproduction.** With an input cue at `[1000,2000]` ms, no FPS/global/split movement, `--snap-ms 700`, and `--end-adjust-ms 600`, the published external-worker bridge accepts `[1700,2300]` with truthful `cues_snapped=1` and `cues_end_adjusted=1`. Both SRT and ASS publish the subtitle and JSON result. The actual engine snaps starts before adjusting ends. At that phase, start `1700` leaves only `300` ms before end `2000`, violating the existing `500` ms minimum. Checking final duration alone hides the impossible intermediate transition.

**Implemented repair.** In `subsync-rs::align::validate_reported_timing`, a changed start now additionally requires:

```rust
before.end_ms.saturating_sub(after.start_ms) >= 500
```

Here `before` is the replayed intermediate cue after FPS rounding, format precision, reported split movement, ASS group clamping, and SRT order repair. It is not the original untransformed source. Saturating subtraction rejects starts at or beyond that end without underflow. The existing final-duration guard remains, as do onset/lead-in validation, separate movement limits, group restrictions, and accurate counters.

**Acceptance evidence.** `sync_end_replay.rs` covers exact `500` ms acceptance and one format unit below it, starts at/past the pre-adjustment end, FPS `24/25` plus a `100` ms split, the independent final-duration guard, and a genuine engine snap followed by an end adjustment. `sync_end_worker_boundary.rs` exercises the actual public supervised CLI for both formats, including a false end count. Invalid results must leave both final names absent, preserve the source, and permit a corrected real-engine result to succeed on the same paths. Rejecting all end-adjusted results, checking the raw source end, or removing the earlier lead-in check would be incomplete repairs.

Worker executable overrides remain trusted programs with ordinary user permissions. This repair validates their output protocol; it does not sandbox executable code or certify perceptual synchronization.

## 3. R02 — Speech beyond the end budget disables a safe partial extension

**Impact and reproduction.** An authored WAV with speech from `1000` to `3100` ms and a cue at `[1000,2000]` produces no end movement with a `600` ms budget. A `1300` ms budget permits an extension, while `0` correctly disables it. A sharper real-audio boundary shows that increasing speech from `2490` to `2500` ms makes the released engine drop an otherwise permitted `600` ms extension entirely. SRT/ASS and standalone, in-process, and supervised execution agree.

The cause was an eligibility filter requiring the whole detected speech endpoint to fit within `cue.end_ms + limit`, before the code applied its existing clamp. The option is documented as maximum movement; continuing speech should receive the safe permitted movement even when the full spoken segment cannot be covered.

**Implemented repair.** `align_cue::refine_ends` retains the continuing-speech overlap and more-than-`140` ms threshold, removes only that inappropriate upper eligibility bound, and clamps `speech_end + 250` to the existing low/high bounds. No new dependency or alternate aligner is introduced. Zero budget, SRT millisecond/ASS centisecond precision, next-cue separation, joined dialogue bounds, intentional ASS overlap groups, audio duration, readable duration, and truthful end-adjusted counts retain their existing roles.

**Acceptance evidence.** `sync_end_bounds.rs` uses independently authored VAD endpoints `2599`, `2600`, `2601`, and `3100`, budgets `0/1/9/10/140/600`, and both formats. It covers a three-cue joined chain, an independent next cue requiring its existing `20` ms gap, reversed-file-order overlapping ASS, an audio-end clamp, short-cue readability, silence trimming, unrelated speech, and the exact `140` ms threshold. Every case also replays the returned report. The real-audio matrix covers the three public execution paths. A moved-end count records movement, not complete speech coverage; a bounded extension can still finish before the dialogue does.

## 4. R03 — Valid sibling embeddings fail a reviewed build

**Impact and reproduction.** The authored logical text `RLE سلام PDF SPACE RLE دنیا PDF` has two valid sibling embedding scopes. Public `prepare`, preserve-reviewed worksheets, and `build` fail with exit `2`: `ValueError: Unbalanced bidi embedding terminator`. Single-embedding and sibling-isolate controls succeed. The migration removed the first opener and final closer based on their spelling, although they belonged to different scopes.

**Implemented repair.** `markup::bidi::flush` tentatively removes a legacy embedding wrapper and validates the remaining format-aware line before committing the migration. If that remainder is unbalanced, it restores the original endpoints. Tags and visible text keep their existing order. It also validates a proposed RTL isolate before retaining it; at the supported nesting limit, boundary marks preserve the valid input without adding an invalid extra level.

**Acceptance evidence.** `rtl_v303_preservation.rs` covers sibling RLE/RLE and RLE/LRE scopes, older RLM-bearing forms, ASS and SRT style-run boundaries, visible text equality, valid nesting depths `1/124/125`, and repeated normalization. Unsupported balanced depth `126` must not be silently erased as stray controls. The public `rtl_v303_workflow.rs` regression imports and builds the actual sibling-scope fixture, validates the emitted bidi structure, and verifies source bytes. A fix limited to `convert` would miss the failing reviewed-build path.

The independent review found an analogous pre-existing limit defect in the LTR branch: `LRI` repeated `125` times around `سلام A`, with matching PDI controls, passes input validation but the old LRE/PDF anchoring raises depth to `126`. A separate regression was run red before correction. The LTR branch now also validates its proposed wrapper and retains only its boundary LRMs when adding another level is unsupported. Both formats and depths `1/124/125` are covered, including visible-text preservation and idempotence. This same-family residual is completed in this PR rather than deferred.

The independent reviewer accepted that follow-up with no remaining concrete blocker in the reviewed scope. The affected four-target RTL suite then passed `76` tests, with no failures or ignored tests.

## 5. R04 — One stray control destroys healthy inner and cross-line scopes

**Impact and reproduction.** Converting `سلام LRI A 12 PDI B RLE` removes the healthy inner LRI/PDI pair along with the unmatched final RLE. Independent FriBidi and native FFmpeg/libass rendering show the Latin order changing from the control's `B A 12` to `A 12 B`. With `LRI A 12 NEWLINE سلام B PDI PDI`, conversion even returns success with an unmatched opener: the English first line retains LRI while blanket cleanup on the Persian second line removes its matching PDI.

**Implemented repair.** `text_pipeline::lines` identifies unmatched controls across the whole readable cue before per-line anchoring. A stack records opener positions and type; a separate isolate index stack makes PDI matching linear rather than repeatedly searching deep malformed input. PDF closes only an embedding at the top; it cannot consume an isolate. PDI closes its matching isolate and embeddings opened within it. An unmatched PDI leaves an existing embedding intact. Only unmatched terminator positions and still-unclosed opener positions are removed. Existing format-aware segmentation protects SRT tags/comments, ASS overrides, font names, and drawing payloads. The per-line deletion of every directional control is removed.

**Acceptance evidence.** Portable regressions cover valid inner/nested scopes with stray openers and closers, PDF/PDI asymmetry, implicit embedding closure by PDI, cross-line scopes beginning on either an English-only or Persian line, SRT newline/`<br>` and ASS `\\N`, style boundaries, protected ASS data, and idempotence. Public conversion tests also validate final cue balance and unchanged input bytes. A successful repair must preserve controls carrying real directional meaning; success cannot be obtained by flattening all bidi structure.

An initial visual suspicion that a Persian word disappeared was independently rejected. Exact comparisons found the Persian region byte-identical, containing `1527` nonblack pixels; changed pixels were confined to Latin content. No renderer, font, or style workaround was added for that disproved hypothesis.

## 11. Optional improvements for a deliberate decision

- **Ambiguous leading ellipses:** current explicit tests intentionally move a leading `...` or `…` before Persian text to the end, while editorial guidance also asks to preserve meaningful continuation. An isolated cue cannot reliably distinguish those intentions. Consider preserving ambiguous ellipses by default or requiring an explicit editorial/opt-in repair, with paired-cue examples, reviewed-workspace/CLI parity, and a recipe migration. This is a policy decision; the repair PR does not silently reverse the newly specified contract.
- **Measured bidi performance:** the new selective matcher is linear, but format segmentation and validation still make several passes. Benchmark realistic long mixed ASS/SRT cues and adversarial controls before consolidating parsers or allocating shared buffers. Retain protected-span and cross-line behavior as acceptance criteria; avoid replacing working code solely to reduce line count.
- **Explain bounded synchronization:** a later diagnostics enhancement could expose why movement stopped at a budget, neighbor, overlap group, or audio boundary. Preserve JSON compatibility and avoid reporting subjective alignment confidence as a measured fact. A separate explicit audio-track selector can build on the existing documented WAV-selection workflow if user demand justifies it.
- **GPU preference with evidence:** investigate acceleration only for a measured bottleneck and a supported cross-platform backend. These control matching and bounded timestamp changes do not justify adding a GPU runtime. Preserve deterministic CPU fallback and verify actual benefit before choosing an upstream library.
