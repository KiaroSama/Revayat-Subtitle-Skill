## 1. Findings and complete repairs

### R304-01 — Valid start targets disappear before candidate scoring

**Impact:** otherwise valid cues remain early even when an eligible recovered onset is inside the configured snap radius. An independent manifestation drops a valid ASS target on an inclusive centisecond boundary. Both occur through standalone `subsync`, in-process sync and supervised-worker sync.

An authored harmonic attack at 2000–2150 ms precedes confirmed activity at 2300–3400 ms. The detector correctly reports anchor 2000 ms and confirmed segment start 2290 ms. With a cue at 1850–3400 ms, radius 350 ms and lead-in 50 ms, the valid target is 1950 ms. v3.0.4 leaves 1850 unchanged; changing only the radius to 400 ms selects 1950. A start of 1880 also fails, while 1890 passes the old inclusive scan boundary.

The candidate iterator previously stopped at confirmed starts greater than `high + lead`. Recovered anchors can precede confirmation by 380 ms, so that cutoff eliminates eligible targets before the exact eligibility and scoring checks see them.

ASS adds a separate rounding allowance. Confirmed onset 2290 ms, original start 1930 ms, radius 350 ms and lead 1 ms yield an unformatted target of 2289 ms. ASS floors it to 2280 ms, exactly inside the window. The old iterator excludes it. SRT preserves millisecond precision, so 2289 is correctly outside its window.

**Implemented algorithm:** for timestamp precision `unit`, enumerate sorted confirmed starts through the saturating ceiling:

`high + lead_in_ms + (unit - 1) + MAX_ONSET_LOOKBACK_MS`

Then apply the existing exact final-target checks. This is a conservative enumeration bound, not permission to exceed the configured radius. A formatted target cannot follow its anchor, which cannot follow its confirmed onset; therefore the existing lower partition remains sound. Do not binary-search the anchor vector: the public VAD contract permits individually valid anchors that are not globally sorted.

The 380 ms constant is shared by extraction, VAD validation and candidate enumeration. No change is made to score ranking, neighbor limits, joined-cue restrictions, intentional ASS overlap, zero-target rejection, the forward movement deadband, the pre-adjustment 500 ms duration requirement, or worker replay.

**Permanent regression target:** [sync_onset_search.rs](../crates/subsync-rs/tests/sync_onset_search.rs). It covers both radius edges at minus/exact/plus 1 ms, maximum lookback, empty-anchor compatibility, ASS rounding, descending anchors, previous-cue and joined limits, duration boundaries, disabled snapping, zero targets, deadband, overlap scoring, intentionally overlapping unsorted ASS events and real authored PCM extraction.

**Observed evidence:** the new target first failed 5 tests and passed 1 control. After repair, the related seven synchronization targets passed all 47 tests. The real executable matrix contains 93 executions: all 15 previously missed targets are corrected and all 78 controls retain their endpoints and tested report fields. All 31 case/format groups agree across the three execution paths. The semantic verifier passed 411 checks, including input and executable hashes.

### R304-02 — A clipped stationary run becomes an invented acoustic onset

**Impact:** a quiet sustained background can advance a cue hundreds of milliseconds despite having no acoustic attack at the selected time. The primary VAD intervals remain correct; the new backtracking layer alone manufactures the earlier anchor.

The decisive eight-second, mono, PCM16 WAV contains a stationary harmonic bed from 500–2300 ms and stronger confirmed activity from 2300–3400 ms. The quiet components are 123, 246, 369 and 738 Hz with gains 450, 360, 150 and 135. Confirmed components are 400, 1200 and 2400 Hz, each at gain 3500. The rest is silence.

Run with zero global/local movement, FPS search disabled, no end adjustment, radius 350 and lead 50. The input cue is [2200,3400] ms. Published v3.0.4 returns **[1860,3400]**, while the appropriate confirmed-onset target is **[2240,3400]**. Reported primary activity overlap falls from 0.925 to approximately 0.720779.

An inspection program linked to the untouched library established raw interval [2290,3410], merged interval [2290,3510] and false anchor 1910. The primary raw, merged and binary activity arrays match the confirmed-only control. The invented anchor is exactly `2290 - 380`.

The scanner starts at `max(confirmed_start - lookback, previous_segment_end)`. It previously labeled that first frame as a run start without checking whether the run was already active immediately before the clipped window. The loud-background contrast filter did not reject this quiet bed. The same cause reproduces at a previous segment's padded end and with a later confirmation after a closure gap.

**Implemented repair:** when a qualifying run begins at the clipped lower bound, reject that run as an onset if the preceding frame also qualifies. Continue scanning subsequent runs. Do not reject every run at the bound: a real attack exactly there remains valid. Keep primary detection, raw islands, gap bridging, padding, local noise floor, persistence, closure and the second-run veto unchanged.

**Permanent regression target:** [vad_onset_boundaries.rs](../crates/subsync-rs/tests/vad_onset_boundaries.rs). Its six tests exercise continuous quiet beds, previous-segment clipping, an attack just outside the window, genuine attacks exactly at/inside both boundaries, and the loud-bed control. SRT and ASS outputs are checked against report replay. The decisive pair also compares primary signal arrays.

**Observed evidence:** unchanged detector behavior failed 3 new tests and passed 3 controls; the repaired target is included in the 47 passing focused audio tests. A frozen 38-case replay classifies 6 accepted regression instances as repaired and 28 controls as preserved. Four diagnostic expectations were explicitly excluded after waveform inspection; they are not relabeled as fixed bugs. Three involved actual primary threshold frames from abrupt signal truncation, and one involved a discontinuity affecting a supposed previous-end boundary. ### R304-03 — FSI direction is computed from ASS syntax instead of displayed prose

**Impact:** near the supported UAX #9 explicit-level limit, valid RTL/LTR wrappers are omitted and mixed Persian/Latin groups render in a different order. Both conversion and reviewed native ASS builds are affected.

Inside an FSI, raw `\h` or soft `\n` contributes an ASCII `h`/`n` to the old checker. libass displays whitespace followed by Persian. At effective parent level 124, the actual RTL FSI can reach level 125; the incorrectly inferred LTR direction would reach 126. The checker therefore declines a wrapper that the visible text supports. Equivalent literal NBSP/space inputs work.

Published conversion reproduced both escape cases. Actual FFmpeg/libass PNGs differ from the correctly isolated comparison; literal whitespace controls match that comparison. Independent FriBidi analysis confirms the group ordering. A separate 176-case reviewed-build matrix contains 88 SRT and 88 ASS cases: only the two ASS hard-space boundary cases fail, one for each outer direction.

The independent completion review found a second path within this same family: reviewed normalization split every raw `\n` before the projection ran. When that escape renders as a space, splitting it invents a paragraph boundary and still loses valid wrappers. A finite 40-case native-build replay reproduced 10 failures and 30 passing controls on the initial repair: RTL and LTR under default mode, header 2 overridden by `\q0`, `\q0` followed by a style reset, Banner overridden by `\q0`, and `\q0` carried across a preceding hard `\N`. Actual PNGs in both directions differ from the expected wrapper, while the expected wrapper matches the literal-space control. This gap was repaired in the same PR, not deferred to a later audit.

**Complete repair contract:** use one format-aware readable-prose projection for effective-level/FSI analysis in both normalization and anchoring. The projection is analysis-only: preserve raw escape, tag and drawing bytes in emitted ASS, and retain the established normalization contract for authored controls. Decode ASS `\h` to nonbreaking space and `\n` according to its effective wrapping mode. Literal SRT backslashes remain literal.

Wrapping context matters. `WrapStyle` supplies the document default; inline `\q` changes the current mode; an absent or invalid `\q` resets to the track default; a Banner event starts in mode 2. A style reset such as `\rDefault` does **not** reset the wrapping mode. Under mode 2, `\n` is a real line break and the FSI must not take a strong character from the next paragraph. Under other modes it is a space. These distinctions were checked against libass 0.17.3 source and actual renderer equivalences before tests were finalized.

Carry the applicable context across display lines, including drawing state. Ignore controls inside tags and drawing data. Preserve whole-cue balanced scopes and previously repaired unmatched-control behavior. Public entry points retain their existing signatures and default behavior; document callers pass the available context internally. The effective-level limit, actual-Latin fallback and idempotence remain enforced.

The normalization delimiter scanner carries that same context independently of output flushing. Split raw `\N` always, and split raw `\n` only in effective mode 2. Pass an explicit delimiter flag to the flushing helper so a text token consisting solely of a soft `\n` cannot accidentally become a break. Keep SRT newline handling unchanged. Do not fix only the later anchoring stage while leaving this earlier normalization split intact.

**Permanent targets:** [rtl_v304_escapes.rs](../crates/revayat-core/tests/rtl_v304_escapes.rs) and [rtl_v304_workflow.rs](../crates/revayat-cli/tests/rtl_v304_workflow.rs). Before production repair, the core target failed 5 tests with 3 passing controls; all 4 CLI tests failed. They exercise hard/soft spaces, literal controls, both outer directions, style runs, real Latin-first fallback, literal SRT escapes, inline wrapping, header mode, Banner and reviewed native ASS output.

The completion gap has its own core and CLI regressions; each failed on the initial repair before the delimiter fix. The final targets contain 10 core tests and 5 CLI tests, including the 40 authored native-build cases and a drawing-context guard. These tests run automatically in the existing workspace CI.

The complete suite also exposed an older fixture that called default ASS `\n` a physical line break. Frozen executable comparisons established that all 30 genuine cross-line cases (`\N`, mode-2 `\n`, and SRT newline across five scope types and two prose placements) retain identical output and strict original scope counts. All 10 default soft-space cases match the unchanged literal-space behavior. The fixture now explicitly selects `\q2` for its cross-line soft break, and the v3.0.4 regression protects default-soft/literal-space equivalence. No production behavior was weakened to satisfy the old assumption.

**Recipe migration is part of this repair.** Generation advances **18 → 19** and normalization **15 → 16**. Project and build schema identities are not repurposed. Original source bytes, worksheet choices, glossary, input identity and prior immutable editions must remain unchanged. New output requires a new edition identity and fresh render approval. Existing migration tests now include the actual 18/15 predecessor as well as older supported recipes.
