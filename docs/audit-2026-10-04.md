## D01 — Unicode regex folding misclassifies literal SRT text as formatting

**Severity: high for content preservation.** The SRT parser and donor converter used Unicode-aware `re.I`, and the formatting-tag boundary used general `\s`. These do not match FFmpeg's ASCII tag grammar.

Reproduce with `<ſ>` (U+017F), `<İ>` (U+0130) or `<ı>` (U+0131). The baseline `visible(text, "srt")` returns an empty string, although native FFmpeg preserves these literal tag-like strings. The baseline donor path turns them into strike/italic controls. Thus `A<ſ>B</ſ>C` loses literal content and changes presentation; a source consisting only of `<ſ>` can also pass an incorrect `action="empty"` decision. `A<i\t>B` and the same boundary using NBSP/thin space are another route: native FFmpeg retains the literal tag-like sequence, but baseline recognition hides it.

**Root cause:** grammar matching is conflated with the Unicode content alphabet. Python deliberately folds additional non-ASCII characters under case-insensitive matching, whereas FFmpeg uses ASCII case operations and a literal ASCII-space parameter delimiter. Merely patching the visibility regex leaves conversion and review accounting inconsistent.

**Implemented correction:** apply `re.ASCII` to the case-insensitive SRT grammar and every corresponding simple-tag validation/substitution. Restrict formatting name/attribute separation to ASCII space. Keep Unicode dialogue untouched; this is not ASCII-encoding the subtitles. The shared tokenizer, visibility checks, requested-font extraction and converter now agree on which strings are syntax and which are prose.

**Acceptance:** literal lookalikes cannot be discarded as empty or turned into ASS controls; tabs/NBSP/thin spaces attached to names remain literal; normal ASCII case variants and binary bold/italic/underline/strike toggles still work. Preserve the 127-UTF-8-byte tag ceiling, known unsupported-markup refusal, current `br` rules, entities, comparisons and documented completed-comment cleanup. The new native corpus compares both visible text and structural controls against actual FFmpeg; an independent nonblank raster comparison covers the long-s literal case.

**Scope:** this does not implement browser HTML, normalize arbitrary Unicode names or silently strip unknown tags. Kelvin-sign and ordinary literal comparisons are controls, not extra claimed bugs. Completed HTML-comment cleanup remains the project's deliberate editorial policy even when the native decoder displays that literal comment string.

## D02 — Removed-comment text fragments break normalization idempotence

**Severity: medium; normalization contract.** `rtl("سلام{note} ", "ass")` produces a different byte sequence when normalized again. Leading/trailing whitespace separated by hidden comments and SRT comment boundaries have related cases; forced LTR can also accumulate wrappers.

**Root cause:** comment removal yields adjacent prose tokens. The first pass selects wrapper boundaries using those separate fragments and excludes whitespace-only fragments. After serialization, the hidden comment is gone, so a subsequent pass sees a single prose run with different boundary placement and fails to recognize the wrapper it previously generated.

**Implemented correction:** a private streaming `_text_runs` adapter coalesces adjacent prose fragments using a list buffer and `join` before `rtl` chooses controls. It never joins across real tags, vector data or retained drawing-object boundaries. It does not destructively clean the original string and reparse its braces, which would regress the previous preservation fixes.

**Acceptance:** one-pass and repeated output are identical across ASS/SRT comment boundaries, spaces/tabs, forced LTR/RTL, mixed-script text, existing embeddings/isolates and real inline controls. Preserve logical content and drawing structures. The suite includes 500 deterministic examples and a many-fragment control without a fragile timing threshold.

**Qualification:** the regular worksheet build path already performs comment cleanup before calling `rtl`, so this is not a claim that every CLI build duplicates controls. It is a directly reproduced defect in the exposed normalization helper and its idempotence contract. The fix also makes that helper safe to compose without relying on a caller's prior cleanup.

## D03 — Python equality admits type-changed immutable metadata

**Severity: medium; artifact-integrity contract.** On a one-cue edition, change `manifest.json`'s `episodes[0].cues` from `1` to `true`. Baseline `load_build` accepts it because Python dictionary comparison considers `True == 1`. Other reproduced/covered substitutions include a float for an integer count, `true` for a provenance index, `0` for `structure_changed: false`, a float recipe version, and `1` for `terms_reviewed: true` in the saved build glossary.

**Root cause:** recomputing the expected immutable record is useful, but ordinary nested Python equality is not a type-preserving JSON comparison. Checking only the top-level manifest version or frame booleans does not cover the remaining immutable structure.

**Implemented correction:** iterative `runtime.same_json` compares exact decoded types before values, dictionary key sets independent of order, and list contents in order. Both build reuse and delivery loading use it for manifests and saved glossaries. The traversal avoids adding a Python-recursion dependency. Existing error wording retains the relevant `modified`/`glossary` context.

**Acceptance:** all covered bool/int/float substitutions refuse in both read and reuse paths; native rendered delivery refuses a changed provenance type before writing a package. Restoring original metadata restores QA. JSON indentation, escaping and key reordering still work. Existing source/subtitle hashes, strict frame validation and recipe identities remain unchanged in purpose.

**Boundary:** no evidence shows arbitrary subtitle-byte forgery or authenticated-review bypass. The finding is acceptance of structurally altered metadata, not a claim of a cryptographic break. The comparison operates on decoded JSON values, not arbitrary cyclic Python objects; the programmatic deep-value test exercises its iterative implementation without claiming that the JSON parser accepts unlimited nesting.
