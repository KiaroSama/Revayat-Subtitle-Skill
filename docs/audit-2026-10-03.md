## A01 — Incorrect ASS block boundaries delete visible text

**Priority: high; preservation contract.** In `markup.py`, the previous `\{[^{}]*\}` search matched an escaped opening brace as a hidden block, and selected an inner block rather than the first closing brace of an outer block. `pieces` also preprocessed comments before finding boundaries, allowing subsequent normalizers to reinterpret changed delimiters.

Authored reproductions through `reviewed_cues(..., action="preserve")`:

- `A\{Important}B` became `A\B`, although libass displays `A{Important}B`.
- `A{comment{inner}VISIBLE}B` became `AB`, although libass displays `AVISIBLE}B`.
- The visible text in `{comment{inner}VISIBLE}` could be misclassified for an `empty` decision.
- Reset-looking literal text inside an escaped opening brace could be treated as a real style reference.

**Implemented:** one disjoint `block_spans` scanner underlies comment removal, prose/drawing tokenization and reset remapping. An unescaped ASS opening brace ends at the first closing brace. Escaped opening braces and unmatched openings stay text. `pieces` no longer destructively pre-cleans and reparses the input. Visibility extraction decodes escaped literal braces without rewriting stored subtitle text. Do not replace this with odd/even backslash parity: libass consumes the immediately escaped brace even following another literal backslash.

**Acceptance:** escaped openings/closings, repeated backslashes, nested openings, hidden comments, unmatched openings, real versus literal resets, inline controls, exactly retained prose, idempotence and nonempty-cue refusal. Actual FFmpeg before/after pixel checks and inspected authored images show restored preservation; normal ASCII/Persian prose and existing parenthesized controls remain covered.

**Boundary:** escaped brace rendering is a libass extension. This fixes the documented FFmpeg/libass route; it does not certify identical behavior in every VSFilter-family player. Never flatten or alter the source to simulate compatibility without an explicit target-player decision.

## A02 — Drawing state is incorrectly reset or ignored, bypassing structural review

**Priority: high; review integrity.** `pieces` previously reset drawing mode on `\r` and skipped commands nested inside `\t`. libass's style reset does not reset `drawing_scale`, and its supported transform parsing can apply `\p` as a state assignment.

Reproductions:

```ass
{\p1}m 0 0 l 20 0 20 20{\r}m 30 0 l 50 0 50 20
{\t(\p1)}m 0 0 l 20 0 20 20
```

Changing the second path in the first example, or the path in the second, changed real rendered pixels but was accepted without `structure_note` because the affected vector data was mislabeled prose.

**Implemented:** drawing-state transitions follow parsed `\p` commands, including supported nested transforms. Bare, named and parenthesized style resets no longer clear drawing mode. An explicit `\p0` still returns to prose. Vector strings remain opaque data: no text normalization or translation is applied to them.

**Acceptance:** reset variants, standard transform arities, parenthesized scalar modes, vector-to-prose transitions, exact vector preservation, rejection of unnoted edits, acceptance of explicitly justified edits, and real pixel changes for the refusal controls. The existing requirement for later visual review remains; a note is not automatic image approval.

## A03 — Staging cleanup masks the true operation outcome

**Priority: medium; transactional recovery.** `runtime.staging_directory` raised cleanup failures from `finally`. A cleanup `PermissionError` replaced an original validation error or cancellation. More importantly, a successful `prepare` published a loadable workspace but reported failure; retry then refused the existing workspace. The same boundary applies to builds.

**Implemented:** capture the created staging directory's device/inode identity. Clean only that owned, unlinked directory within its parent. Preserve a replacement directory/link instead of deleting it. Expected cleanup errors produce a timestamped WARNING with a recovery path without replacing the original exception or changing a successful publication into failure. No validation or publication failure is suppressed.

**Acceptance:** primary exception identity, cancellation identity, successful import followed by `load`, successful build followed by reuse, ordinary cleanup, and preservation of an unrelated directory substituted at the staging path. The tests restore fault injection before their own cleanup. This is outcome-safe cleanup, not an assertion of an adversarial race-free filesystem sandbox.

## A04 — Donor merging drops rendering-global settings

**Priority: medium; presentation fidelity.** `merge_donor` checked only PlayRes, WrapStyle and ScaledBorderAndShadow. A donor with `Kerning: no` merged into a base with `Kerning: yes` without refusal; the same authored `AVAVAV` text rendered differently after merging.

**Implemented:** preflight the compatible track-level settings before adding styles or mutating donor cues: PlayRes, LayoutRes, WrapStyle, ScaledBorderAndShadow, Kerning, YCbCr Matrix, Language, Collisions and Timer. Report differing key names and require deliberate alignment. Matching headers and donors with no retained contribution remain accepted.

**Acceptance:** each additional key is tested, mismatch rejection leaves the base unchanged, compatible donors merge, empty donor contribution remains a no-op, and real kerning differences are demonstrated in the renderer tier. LayoutRes and the remaining keys are conservative fidelity guards supported by upstream semantics; they are not each claimed to have produced a visible difference in the local renderer. Explicitly different versus absent/default headers remain a deliberate reconciliation boundary rather than an automatic guess.

## A05 — Unterminated SRT comments cause repeated suffix rescanning

**Priority: medium for bounded processing.** The global lazy comment regex repeatedly tried to find a closing marker for every unmatched `<!--`. Authored baseline runs for 1000/2000/4000 openings took approximately 0.016/0.063/0.247 seconds, consistent with quadratic rescanning despite the input-size limit.

**Implemented:** the shared span scanner searches comment closers once per disjoint region and remembers when no later closer exists. Unterminated text remains literal, preserving the prior contract. ASS scanning similarly avoids a regex search over repeated unmatched opening braces.

**Acceptance:** a bounded subprocess processes 50000 unmatched SRT comment openings and 50000 unmatched ASS openings without changing the text. Ordinary multiline comments, real formatting, current FFmpeg-style `br` handling, tabs/nonbreaking-space literals and entities remain covered. The regression uses a generous timeout, not a fragile timing ratio. This is a specific bounded-scanning repair, not a universal complexity proof for all regular expressions in the project.
