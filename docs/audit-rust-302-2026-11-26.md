## 2. A01 — A nearer noise burst can worsen dialogue alignment

**Reproduction.** An authored 4-second, mono 16 kHz WAV contains bursts at 1160–1220 ms and 1810–3200 ms. A single SRT cue spans 1400–3200 ms. Disable global/local shifts and FPS search. The published executable chooses 1100 ms with the default 50 ms lead-in: the reported overlap falls from `0.77777778` to `0.75238095`. With `--lead-in-ms 0`, it chooses 1150 ms and still reduces overlap. These are public executable results, not just hand-computed estimates.

**Cause and implemented fix.** The new onset selector removed its quality check and ranked eligible candidates by distance alone. `align.rs::snap_start` now filters candidates by their speech fraction before distance ranking. It measures each candidate from the actual speech onset to the cue end, excluding the intended lead-in from the quality comparison, and requires that fraction to be at least the unsnapped fraction. A zero-length scored interval is refused. Original distance, minimum-duration, neighbor, join-chain, and overlapping-ASS restrictions remain in force.

**Acceptance.** The corrected actual WAV case selects 1750 ms at default lead-in, improving measured overlap to `0.96551724`; with lead-in disabled, it preserves the 1400 ms start. `sync_snap_lead.rs` independently supplies a binary VAD oracle and checks both modes, output endpoints, snapped count, report quality, and replay. Retain joined-cue, reversed/overlapping ASS, FPS drift and noisy-unity regressions. Do not make a test pass by removing the lead-in feature or relaxing neighboring-cue constraints.

## 3. A02 — Worker replay omits the implied speech onset

**Reproduction.** For 4000 ms of audio, an input cue at 3900–4900 ms, zero global/local shifts, snap allowance 100 ms, and lead-in 50 ms, an authored worker returns 3990–4900 ms with truthful delta and snapped statistics. The old bridge accepts and publishes it. The earliest onset implied by that displayed start is 4040 ms, beyond the audio.

**Cause and implemented fix.** Replay checked only whether the displayed start preceded the reported duration. `validate_reported_timing` now checks `output_start.saturating_add(lead_in_ms) < audio_duration_ms` for an actually changed/snapped start. Unchanged starts and cue ends may still extend beyond the media; the existing timing-plan replay, precision, group shifts, repairs, and counter validation remain unchanged.

**Acceptance.** Library tests cover equality, just beyond, and just within the duration for SRT and ASS. The existing actual external-worker integration test now includes an impossible lead-in case: it must fail before either final destination exists, then successfully reuse those same names with a corrected result. The real public CLI reproduction exits `2` and does not publish. This checks protocol consistency; the bridge does not possess the worker's VAD and does not certify perceptual alignment or sandbox the selected executable.

## 4. A03 — Bold inheritance chooses the wrong style and numeric meaning

**Reproduction.** A valid ASS can declare `default` before the separate exact `Default`, with opposite Bold values. The source reader's event references resolve to the canonical `Default`; inline resets may deliberately reference `default`. The new first case-insensitive lookup can strip or introduce bold on the actual Default track. Hexadecimal values such as `&HFFFFFFFF` lose bold, whereas decimal `0.5` and `4294967296` incorrectly introduce it. Native FFmpeg/libass renders those latter values as integer zero.

**Implemented fix.** `source_default_style_is_bold` selects the exact parsed `Default` declaration. Numeric values follow libass's integer-prefix and modulo-2^32 behavior, including hexadecimal markers, an optional sign, and its optional inner hexadecimal prefix. The existing explicit `true` compatibility remains. Explicit `--bold`/`--no-bold` and caller-provided style rows retain precedence. This does not rename styles or alter literal inline reset names.

An independent review exposed an additional boundary in the same parser: `&H0x1`, `&H-0x1`, and `0x0XFF` all render bold in libass. Those forms were red before the follow-up correction and are included in the final table. Style-token whitespace is judged after libass's tokenization, which strips leading ASCII space/tab; nonbreaking-space and vertical-tab controls prevent indiscriminate trimming.

**Acceptance.** The actual `convert` and `translator-ass` regression checks canonical/alias declarations, inherited numeric meaning, explicit override precedence, and preserved named reset references. Eleven renderer/CLI numeric pairs include nested hexadecimal prefixes, signs, padding, missing digits, and wrapped zero. Do not repair only one spelling while retaining a floating-point interpretation for the remaining integer field.

## 5. A04 — Abbreviated ASS layouts discard generated settings

**Reproduction.** The parser and existing contract tests accept abbreviated V4+ Styles Formats. On a source omitting Bold or MarginL, `convert` and `translator-ass` report success after dropping explicit `--bold`/`--margin-l 27` and other generated defaults. A related reviewed-workspace path repeats this when an SRT donor needs a Default style on a non-Default ASS base. This is not limited to a missing command-line flag: the generated row was projected into only the source's old columns.

**Implemented fix.** A shared `insert_generated_style` helper adds missing generated fields and widens inherited rows with renderer-equivalent implicit values: Fontname `Arial`, ScaleX/ScaleY `100`, and zero for other missing native fields. Existing field values, custom columns, and inline style references are preserved. Missing fields are prepended, keeping the original terminal field last and ensuring a previously custom layout remains custom for libass's implicit `ScaledBorderAndShadow` behavior. Complete layouts are not unnecessarily reordered.

Both conversion and `workflow::review::donor` use the shared operation. When a subsequent ASS donor follows the SRT insertion, compatibility is checked against the base's original declared layout. Only the known widening of formerly identical schemas is reconciled; differing event formats, original style schemas, track settings, namespace collisions, and incompatible fonts retain their validation. A rejected donor does not partly mutate the base.

Because this fixes sealed workspace output, generation advances from `15` to `16`; normalization remains `13`. On the same reviewed input identity, an actual baseline edition `34a0d47f…` becomes a new edition `14116a0d…`. Generated Default now gets MarginL `10`, while inherited Signs retains its effective margin `0`. All six files in the old edition, including real FFmpeg images and their receipt, remain byte-identical. The new edition has no inherited render approval and requires fresh review.

**Acceptance.** Six permanent CLI/workspace tests cover the shared style behavior, a reviewed three-source episode (ASS base, SRT donor, later compatible ASS donor), genuine schema incompatibility, exact numeric inheritance, and custom-layout scaling. Eighteen authored CLI variants previously had eight mismatches and now match expectations. Twenty-two native renderer comparisons verified that explicitly supplying each missing inherited-field value preserves the original frame and selected font. Do not close this item with only the public converter fixed while leaving the reviewed-build sibling path unchanged.

## 6. A05 — Extraction stages restart the timeout

**Reproduction.** A controlled 0.63-second probe plus 0.63-second decode around real FFmpeg lets the released standalone executable return success and publish after approximately 1.55 seconds with `--ffmpeg-timeout 1`. If Center decoding exhausts its limit, the old path starts another mono decoder with a fresh budget. A real FFprobe blocked on an authored FIFO also consumes the full budget, after which the old implementation still attempts the next executable.

**Implemented fix.** `FfmpegDeadline` carries one monotonic start and total budget through probing, Center decoding, and fallback. The probe retains its independent maximum of 15 seconds within that total. Cancellation and remaining time are checked before another child starts, during waiting, and before returning decoded PCM. Legitimate absent/uncheckable/silent-Center fallback uses only the remaining budget. Owned-process termination remains mandatory and has its existing separate bounded cleanup allowance.

**Acceptance.** The controlled 1-second reproduction now returns timeout at approximately 1.01 seconds and does not publish. A process trace confirms that an expired Center decode does not launch the mono decoder. The permanent Unix FIFO regression checks which failure occurs rather than requiring a fragile millisecond timing margin, and checks both destination names. Existing cancellation, inherited-handle/descendant cleanup, real FFmpeg, and media-clock controls remain green. Raising timeouts or accepting partial PCM is not remediation.

## 7. A06 — Front Center detection misses layouts and misreads labels

**Reproduction.** Authored real `7.1(wide-side)` audio has speech in FC and interfering content elsewhere. Release 3.0.2 downmixes it and reports no usable speech. Equivalent `5.1` content extracts exact FC samples and succeeds. The hardcoded alias list omitted FC-containing layouts. Substring matching also failed to distinguish physical channel identifiers from other channel names or display labels.

**Implemented fix.** Detection includes the documented FC-containing standard layouts and checks exact identifiers in custom descriptions. Probe output is now typed single-stream JSON using the existing serde dependency, avoiding CSV quoting errors. Custom descriptions must have the reported number of channel tokens; ambiguous descriptions fall back safely instead of treating a display-label fragment as a new physical channel.

The independent review exercised real FFprobe descriptions containing `FC@A,B` and `BC@X+FC`. JSON preserves comma-bearing names. Cardinality validation rejects the latter's ambiguous plus-delimited description; `TFC`, `BFC`, and a label named FC do not become physical FC. These focused follow-up cases were red before correction and are permanent unit regressions using real FFprobe input.

**Acceptance.** The actual `5.1` and `7.1(wide-side)` fixtures now return the exact direct-FC PCM bytes and complete alignment. The permanent extraction test checks authored sample value `4096` instead of mirroring the implementation; a silent-Center control compares to actual FFmpeg mono output. Preserve source selection (`0:a:0`), initial delays/gaps, the shared deadline, and cancellation. Selecting a different audio track remains a documented explicit-WAV workflow, not an undocumented heuristic.
